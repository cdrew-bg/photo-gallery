# Dev workflow for this repo

This file is generated by `scripts/gen-dev-skill.mjs` from `package.json`. Do not hand-edit — run `node scripts/gen-dev-skill.mjs`.

## Non-negotiables

- TypeScript strict, no `any`, no un-sanctioned `as` casts. Node 22, pnpm only.
- No comments anywhere (lint-enforced). WHY-knowledge goes to `docs/context/code-notes.md` or an ADR.
- Read env only via `loadEnv()` in `lib/env.ts`. Log via the pino logger in `lib/logger.ts` (static message + metadata). Catch blocks log XOR throw.
- Size/shape limits: 2 params, 50 lines/fn (100 tsx), 250 lines/file, complexity 10, depth 4. Named `UPPER_SNAKE` constants for magic numbers.
- Boundary Zod schemas chain `.strict()`. Dates: ISO-8601 UTC, `z.string().datetime({ offset: true })`, never `z.date()`.
- Tests are `*.test.ts(x)` colocated; mock only at system boundaries. Full standards live in `CLAUDE.md`.

## Custom lint rules (enforced)

These project-specific rules are enforced by `pnpm lint:guardrails`. Write code that satisfies them from the start — do not wait for the gate to catch a violation.

| Rule | WHY |
| --- | --- |
| `local/no-comments` | No comments anywhere; WHY-knowledge goes to docs/context/code-notes.md or an ADR. |
| `local/zod-strict-boundary` | Boundary z.object() must chain .strict() so unknown keys are rejected. |
| `local/structured-logging` | Log a static message plus a metadata object; never interpolate values. |
| `local/no-log-and-throw` | A catch block logs XOR throws — never both, or the error is reported twice. |
| `local/test-file-location` | Tests are *.test.ts(x) colocated; no *.spec.ts or __tests__/ folders. |
| `local/no-internal-vi-mock` | Mock only at system boundaries; inject internal dependencies instead. |
| `local/no-server-date-formatting` | Server emits ISO-8601 UTC; locale formatting lives in the client layer. |
| `local/require-datetime-zod` | Boundary dates are z.string().datetime({ offset: true }), never z.date(). |
| `local/no-naive-date-parse` | Parse only ISO strings; no Date.parse() or new Date(nonIso). |
| `local/boundary-schema-location` | Define request-input z.object() schemas in *.schema.ts (route/API surface) so strict/datetime rules apply. |
| `local/no-raw-error-at-boundary` | Throw AppError families from lib/errors.ts at boundaries, never a raw built-in Error. |
| `local/route-exports-only-handlers` | route.ts exports only HTTP handlers and Next route config; logic lives in lib/. |
| `local/no-deep-module-import` | Import a module by its public entry, never by reaching into its internal files. |
| `local/filename-convention` | Source file names are kebab-case; Next.js special files already comply and dynamic [param] segments are exempt. |
| `local/declarations-at-top` | Constants, type aliases, interfaces and enums are declared at the top of the file, before any function or class implementation. |
| `local/single-type-per-file` | A file declares at most one top-level interface, type alias, or class; each gets its own file (grouped Zod *.schema.ts files exempt). |
| `local/filename-role-suffix` | Every source file states its role in its name (.component.tsx, .interface.ts, .type.ts, .class.ts, .enum.ts, .schema.ts, .hook.ts, .service.ts); framework-reserved and test files are exempt. |
| `local/kind-folder` | Interface, type, class and enum files live in a kind-named folder within their directory — interfaces/, types/, classes/, enums/. |

## How to run checks

Drive all checks through the `dev` MCP tools below instead of raw `pnpm` in Bash — they run in the repo root and return pass/fail plus captured output. Use the `mcp__dev__*` names.

Inner loop while editing: `mcp__dev__quick`. Fixing a specific gate: run that gate's tool. Before any commit or PR: `mcp__dev__verify` must pass. If a gate fails, fix the code — never weaken the gate, lint config, or hooks (they are protected).

## Tools

| Tool | Runs | Effect | Purpose |
| --- | --- | --- | --- |
| `mcp__dev__verify` | `pnpm verify` | read-only | Run every static gate (lint, types, quality, guardrails, typed, dup, deps). Run before any PR. |
| `mcp__dev__run_gates` | `pnpm check:agent` | read-only | Run the agent gate sweep and write a machine-readable pass/fail report to .agent/report.json. |
| `mcp__dev__lint` | `pnpm lint` | read-only | Base eslint correctness and style across all TS/TSX. |
| `mcp__dev__typecheck` | `pnpm typecheck` | read-only | TypeScript strict compile (tsc --noEmit); no any, no unsound casts. |
| `mcp__dev__quality` | `pnpm lint:quality` | read-only | Duplication, cognitive complexity, and the as-unknown-as ban. |
| `mcp__dev__guardrails` | `pnpm lint:guardrails` | read-only | AI discipline: comment ban, size and shape limits, named constants, env access, UTC dates. |
| `mcp__dev__typed` | `pnpm lint:typed` | read-only | Type-aware: no floating or misused promises, switch exhaustiveness, only-throw-error. |
| `mcp__dev__dup` | `pnpm dup` | read-only | jscpd copy-paste detection under 3 percent. |
| `mcp__dev__deps` | `pnpm lint:deps` | read-only | knip: no unlisted dependencies or binaries. |
| `mcp__dev__deadcode` | `pnpm lint:deadcode` | read-only | knip dead-code ratchet: unused counts may only shrink. |
| `mcp__dev__lint_gates` | `pnpm lint:gates` | read-only | Keep the CLAUDE.md gate table in sync with the gate scripts. |
| `mcp__dev__test` | `pnpm test` | read-only | Run the vitest suite once. |
| `mcp__dev__coverage` | `pnpm test:coverage-ratchet` | read-only | Fail if line coverage falls below the recorded floor. |
| `mcp__dev__format_check` | `pnpm format:check` | read-only | Check prettier formatting without writing. |
| `mcp__dev__format` | `pnpm format` | writes | Write prettier formatting across the tracked source globs. |
| `mcp__dev__quick` | `pnpm check:quick` | read-only | Fast inner loop: typecheck plus vitest on changed files. |

## Self-update

Editing a script in `package.json` and running `node scripts/gen-dev-skill.mjs` regenerates `tools/dev-mcp/tools.json` and this file; the MCP server reads the manifest at startup. `node scripts/gen-dev-skill.mjs --check` fails on drift and is wired into lefthook `pre-commit` (verify) and `post-merge` (re-sync) once the snippets in `tools/dev-mcp/README.md` are applied.
